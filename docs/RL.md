# 强化学习适配性评估 RL

这份文档回答一个问题：**当前这套代码适不适合拿来训练强化学习的派梯策略。**
结论是：**适合当环境，不适合直接跑策略梯度。** 缺的东西不多，但缺的那部分
恰好是策略梯度必需的。下面把家底、缺口、补法写清楚。

只提方案，没有实现。

---

## 1. 强化学习需要什么

一个策略梯度算法要的四样东西：

| 需要 | 含义 |
| --- | --- |
| 环境可重置 | 从同一个初始状态反复开始，最好还能固定随机性 |
| 逐步接口 | 一次给出「当前状态、所采取的动作、这一步的奖励」，然后等下一步 |
| 观测向量 | 策略网络的输入，固定长度、固定顺序 |
| 奖励信号 | 每一步或每回合末给一个数 |

拿这四条去对当前代码。

---

## 2. 已经有的家底

### 2.1 回合成本极低

单次仿真在毫秒量级。一栋十八层的楼跑一次早高峰，实测不到一毫秒，见
[`PERFORMANCE.md`](PERFORMANCE.md) 第 2.1 节。

```
单核每秒约 1200 个回合
十四核并行约 16000 个回合
```

一条轨迹按五十步算，一小时能采到上亿个状态转移。**这个量级足够做离线强化学习。**

### 2.2 随机性完全受控

根种子进，全部随机流由 `splitmix64` 派生，同一份种子逐位可复现。这一条对强化
学习比听起来更重要。用公共随机数跑两套策略，客流完全相同，比较出来的差异就是
策略差异，不是两批不同乘客的差异。样本效率能高一个量级。

### 2.3 环境无副作用

`tihu-core` 不碰磁盘、不碰网络、不依赖系统时间。放进并行 worker 里跑，不需要
任何同步。算子可以直接开几十个进程采数据。

---

## 3. 缺的三样

### 3.1 回合是整段跑完的，没有逐步接口

`run()` 一口气把整场仿真跑到时间窗口结束，然后交回汇总指标。中间没有暂停，
没有「执行一个动作再观察」。

派梯在物理上本来就是离散事件，一次决策影响很久之后的结果。硬拆成固定步长去
迁就强化学习，会同时破坏事件驱动的精度与逐位可复现，代价太大。

### 3.2 奖励只在末尾出现

现在能拿到的是整场跑完的聚合指标，比如平均等待、被挤率。想做逐步奖励，需要在
每次停靠、每次上下客时把当下的收益记下来。

### 3.3 策略 trait 是只读的

`Router::next_leg` 与 `Assigner::assign` 都取 `&self`。策略网络的参数要更新，
就得在只读接口里改内部状态。这不是死结，但需要一层显式的包装。

---

## 4. 建议的改法

### 4.1 先做不动机的：黑盒优化

**推荐先走这条路。** 把 `Router` 与 `Assigner` 的参数当成搜索空间，用进化算法或
贝叶斯优化去搜。

这么做不需要动内核一行。回合已经很快，公共随机数把噪声压得很低，几十万次评估
在一台机上完全跑得动。`docs/PLAN.md` 里 `evolve` 与 `nash` 两个命令本来就是为
这类搜索准备的。

局限也很清楚。它只能搜少量连续参数，搜不出「看一百个数做决策」的神经网络。

### 4.2 真要做策略梯度：加一个观察钩子

在内核里加一个 `Observer` 回调，在决策点把三样东西吐出去。

```rust
pub trait Observer {
    /// 一次决策：谁在什么状态下选了哪个动作
    fn on_decision(&mut self, car: CarId, obs: &[f32], action: Action);

    /// 一次结算：这一步拿了多少奖励
    fn on_reward(&mut self, car: CarId, reward: f32);
}
```

调用点有三处，都是一次函数调用，不开销可忽略：

```
next_leg   被调用时    → 状态是 RunView 拍出来的定长向量，动作是 Leg
assign     被调用时    → 状态是 SystemView 拍出来的定长向量，动作是 CarId
到站结算   每次停靠后  → 奖励按等待时间、被挤次数、载客率加权给一个数
```

状态向量要定长。`RunView` 里的 `car_calls` 与 `mine` 是变长的，拍成向量时得按
楼层固定展开，空位填零。这是唯一需要新写的一块。

### 4.3 策略用 `RefCell` 接进来

`&self` 的只读接口配神经网络的参数更新，用 `RefCell` 或 `Cell` 就够。仓库里
`RoundRobin` 已经在用 `Cell` 存游标，这条路是通的。

```rust
struct NeuralRouter {
    net: RefCell<Network>,
}
```

单线程训练时这样写没有额外后缀。多线程并行采样时换成每线程一份网络副本，
参数更新走主线程汇总。

### 4.4 逐步 API 留到最后

只有真要跑 PPO、SAC 这类在线算法，才需要「暂停环境、外部给动作、恢复」这种
逐步接口。那意味着把主循环改造成状态机，代价不小，而且和事件驱动的精度有冲突。

**先不要做。** 用观察钩子采离线数据，配合现有的黑盒搜索，能覆盖绝大多数需求。

---

## 5. 一句话总结

当前代码是一个**快、确定、无副作用**的环境，拿来采数据与做黑盒搜索很合适。
要跑在线策略梯度，缺一个观察钩子与一层 `RefCell` 包装。逐步接口的代价最大，
留到确实需要时再动。
